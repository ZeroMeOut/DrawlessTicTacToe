## Installation

Install with uv

```bash
  git clone https://github.com/ZeroMeOut/DrawlessTicTacToe.git
  cd DrawlessTicTacToe
  uv sync
```
    
## Usage

If you want access to the llm, create a `.env` file in the DrawlessTicTacToe dir and add `GEMINI_API_KEY='YOUR-API-KEY'`, where `YOUR-API-KEY` is your token from https://aistudio.google.com. Ideally a paid tier.

Then in that same dir run `python main.py` and you are good to go :).

## Thoughts
Initially I wanted to write this is rust while revision rust, but I figured it would be easier to make a prototype in python. The game is your typical tictactoe, but if there two spaces left it removes the oldest added move (hence FIFO). The `tictactoe.py` controls most of the logic, with variables that can store states and other important functions like resetting, reverting, and checking winning conditions. 

The `minimax.py` was initally nothing out of the ordinary, but I soon realised that it was making very werid and questionable moves because of the FIFO nature of the game. After some tweaks like making it consider certain threats and fixing bug in the revert function in my `tictactoe.py` it was finally in a state that I liked.

The `llmpayer.py`  controls how the llm plays the game, well not the llm per-say, just a code the llm generates to play the game. Initally I just passed the game state of the board to the llm for it to give it's predictions directly, but it was slow as hell and the predictions were completely terrible. I tried online and offline models and the results were the same, which was like ok, I need a new plan. So I changed it to what it is rn, the llm generates code, the code is used to play against my minimax, and regardless of if the llm loses or wins it takes in the history of the game (looks like list[tuple[int, int, str]]) and the code it generated to improve on it. This works so well, with the generated llm code sometimes beating mine first try. You can also see the reasoning of the mode after it has generated the code, but not the code changes tho, idk a good way of showing that in the terminal. Oh all it's only Gemini models cause that's the one I bought credits for ages ago so it came in clutch on this project.

As for the UI, I used curses (it's a python lib). Honestly for that most if not all the code was generated by Claude. I wanted to move on to a different project (modding Silksong for RL, learning C# atm) which was more intersting imo. Anyways, till next time :).
